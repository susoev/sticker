# Sticker

Стикер со списком строк поверх окон Windows. Синхронизируется с `https://alid.in/sticker/`.

## Для агентов, которые вносят правки

- **Push в `main` = релиз.** GitHub Actions (`.github/workflows/release.yml`) собирает установщик на Windows и публикует релиз `v1.1.<N>`. Установленные копии проверяют обновления раз в час (и через 10 с после запуска), скачивают и перезапускаются, когда стикер не в фокусе.
- Версию в `package.json` руками не меняй — её выставляет CI.
- Перед push проверь, что приложение стартует: `npm ci && npm start`.
- Секретов в репозитории нет и быть не должно: `api_key` хранится только в локальном конфиге пользователя.

## Устройство

| Файл | Что делает |
|---|---|
| `src/main.js` | Окно поверх всех, трей, автозапуск, IPC, автообновление, лог |
| `src/config.js` | Дефолты конфига, валидация (JSON, типы, hex-цвет, наличие шрифта в системе) |
| `src/store.js` | Локальные `notes.json` (+ `notes.backup.json`) и `state.json` (позиция окна) |
| `src/sync.js` | Синхронизация: раз в `sync_interval_sec` GET, побеждает больший `updated_at`; локальная правка → POST через 1,5 с |
| `src/renderer/sticker.*` | Интерфейс стикера; все цвета выводятся из одного `color` |
| `src/renderer/config.*` | Окно редактирования конфига |

Данные пользователя: `%APPDATA%\Sticker\` — `config.json`, `notes.json`, `state.json`, `sticker.log`.

## Протокол сервера

`GET /sticker/` → `{"updated_at": <ms>, "lines": [{"id","text"}]}`
`POST /sticker/` с тем же документом → `{"ok":true}` или `{"ok":false,"reason":"stale"}` (сервер принимает только строго больший `updated_at`).
Ключ — заголовок `X-Api-Key`. URL обязательно со слэшем на конце.

## Локальная сборка

```bash
npm ci
npm start          # запуск из исходников
npm run dist       # установщик в dist/ без публикации
```
