# Задача: бэкенд синхронизации для приложения «Sticker»

Сделай минимальный бэкенд на **PHP** (без фреймворков и без баз данных: только текстовые файлы) по адресу **https://alid.in/sticker/**.

## Что это

Десктопное приложение-стикер хранит список текстовых строк. Пользователь один. Каждые N секунд приложение скачивает документ с сервера и сравнивает поле `updated_at`. Если на сервере версия новее, приложение забирает её себе. Если новее локальная, приложение отправляет её на сервер. Позже появится мобильный клиент с тем же протоколом.

## Структура

```
/sticker/
  index.php        ← единственная точка входа
  config.php       ← API_KEY и настройки, НЕ отдаётся наружу
  data/            ← закрыт от веба (.htaccess "Require all denied" + пустой index.html)
    notes.json     ← текущий документ
    backups/       ← копии предыдущих версий
```

## Формат документа

```json
{
  "updated_at": 1793328220161,
  "lines": [
    { "id": "b", "text": "Позвонить в банк" },
    { "id": "3f1c…", "text": "Любой текст в одну строку" }
  ]
}
```

- `updated_at` — целое число, миллисекунды Unix-времени. Его выставляет **клиент**. Сервер это поле не меняет.
- `lines` — массив объектов `{id: string, text: string}`. Порядок значим.

## Авторизация

Ключ передаётся в заголовке `X-Api-Key`. Как запасной вариант принимай query-параметр `?key=` (пригодится для отладки в браузере). Сравнение делай через `hash_equals`. Если ключ неверный, отвечай `401` и `{"error":"unauthorized"}`.

## Эндпоинты (всё на `/sticker/`, то есть на `index.php`)

### GET /sticker/
- Возвращает текущий `notes.json`.
- Если файла ещё нет, отдаёт `{"updated_at":0,"lines":[]}`.
- Ответ `200`, `Content-Type: application/json; charset=utf-8`, плюс `Cache-Control: no-store`.

### POST /sticker/
- Тело — JSON-документ в формате выше.
- Валидация:
  - тело — валидный JSON;
  - `updated_at` — целое число больше 0;
  - `lines` — массив, в каждом элементе строковые `id` и `text`;
  - не больше 1000 строк, тело не больше 1 МБ.

  При ошибке отвечай `400` и `{"error":"…описание…"}`.
- **Защита от перезаписи старым:** если `updated_at` в запросе **меньше или равен** серверному, файл не трогай и ответь `200` с `{"ok":false,"reason":"stale","updated_at":<серверное>}`.
- Иначе:
  1. Скопируй текущий `notes.json` в `backups/notes-<серверный updated_at>.json`. Храни **50** последних бэкапов, более старые удаляй.
  2. Запиши новый документ атомарно: во временный файл, затем `rename`, под `flock` на lock-файле.
  3. Сохраняй JSON с `JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT`, чтобы файл читался глазами.
  4. Ответь `200` и `{"ok":true,"updated_at":<новое>}`.

### Остальные методы
`405`.

## Прочее
- Кодировка UTF-8 везде, кириллица должна сохраняться как есть.
- CORS не нужен: клиент — десктопное приложение.
- Ключ API — длинная случайная строка, хранится в `config.php`. **Сгенерируй его и сообщи мне.** Я впишу его в конфиг приложения в поле `api_key`.
- Проверь, что `data/` и `config.php` не открываются из браузера напрямую.

## Проверка, которую нужно выполнить и показать вывод
```bash
K=<ключ>
curl -s https://alid.in/sticker/ -H "X-Api-Key: $K"                      # {"updated_at":0,"lines":[]}
curl -s -X POST https://alid.in/sticker/ -H "X-Api-Key: $K" \
     -d '{"updated_at":1000,"lines":[{"id":"a","text":"Привет"}]}'       # ok:true
curl -s -X POST https://alid.in/sticker/ -H "X-Api-Key: $K" \
     -d '{"updated_at":500,"lines":[]}'                                   # ok:false, stale
curl -s https://alid.in/sticker/ -H "X-Api-Key: $K"                      # строка "Привет"
curl -s -o /dev/null -w "%{http_code}\n" https://alid.in/sticker/        # 401
curl -s -o /dev/null -w "%{http_code}\n" https://alid.in/sticker/data/notes.json  # 403
```
После проверки очисти тестовые данные: удали `notes.json` и бэкапы.
